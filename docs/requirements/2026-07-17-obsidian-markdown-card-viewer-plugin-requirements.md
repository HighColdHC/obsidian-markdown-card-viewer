# Obsidian Markdown 卡片查看插件需求

> 版本：v1.1
> 日期：2026-07-26
> 状态：当前插件开发需求
> 产品基线：[`../product/2026-07-17-obsidian-markdown-card-viewer-requirements.md`](../product/2026-07-17-obsidian-markdown-card-viewer-requirements.md)
> 视觉原型：[`../../prototype/markdown-card-viewer/index.html`](../../prototype/markdown-card-viewer/index.html)

## 1. 目标

开发一个只读的 Obsidian Desktop 插件：

- 一个 Markdown 文件显示为一张卡片；
- 一个文件夹显示为多卡片视图；
- 文件夹默认使用关系图谱；
- 用户可以切换网格、瀑布流和列表；
- 插件只保存自己的布局设置，不修改 Vault 内容。
- 插件可按 [`2026-07-26-infoos-card-pull-requirements.md`](2026-07-26-infoos-card-pull-requirements.md) 手动拉取 InfoOS 卡片，并只写入受管目录。

## 2. 产品边界

插件负责读取和显示 Markdown，以及通过冻结接口手动拉取 InfoOS 卡片。

插件不负责：

- 除手动 InfoOS 拉取外的采集、同步、导入或自动落地内容；
- 创建、编辑、移动、重命名、删除或归档文件；
- 卡片状态、工作流或流转记录；
- AI、Agent、脚本或 skill；
- 搜索、筛选和用户排序；
- 移动端；
- 独立服务或数据库。

任何新增上述能力的实现都属于产品范围变更。

## 3. Obsidian 宿主边界

Obsidian 原生提供：

- Ribbon；
- 文件资源管理器；
- Markdown 编辑器；
- Vault 文件管理；
- 主题和 Markdown 基础渲染。

插件只新增：

- 一个 Ribbon 入口；
- 一个自定义卡片查看视图；
- 视图顶部工具栏；
- 单卡、图谱、网格、瀑布流和列表。

HTML 原型中的左侧 Ribbon 和文件树只是 Obsidian 环境示意，正式插件不得重新实现文件管理器。

## 4. 进入插件

点击 Ribbon 后按以下顺序打开：

1. 当前活动文件是 Markdown：打开单卡视图；
2. 当前存在文件夹上下文：打开该文件夹视图；
3. 没有上下文：恢复上次视图；
4. 没有历史状态：打开 Vault 根目录。

插件应复用已有视图，不重复创建相同 Leaf。用户主动拆分 Workspace 时可以存在多个实例。

如果 Obsidian API 无法可靠获取文件树选中的目录，则使用当前活动 Markdown 的父目录作为文件夹上下文，不得为此复制一套文件树。

## 5. Markdown 卡片

### 5.1 文件识别

- 所有 `.md` 文件都可以显示；
- 不要求专属 frontmatter 或 `card: true`；
- 标题优先使用一级标题，没有时使用文件名；
- 附件不单独成为卡片；
- 文件解析失败时显示错误卡片，不静默跳过，也不修改源文件。

### 5.2 原生渲染

插件使用 Obsidian 原生 Markdown 渲染能力，并传入正确的源文件路径。

必须支持：

- 标题、列表、任务列表、表格和引用；
- 代码块、数学公式和 Callout；
- WikiLink、标签和脚注；
- 图片、音频、视频、PDF和 Obsidian 嵌入；
- 当前 Obsidian 主题。

多个图片和音视频必须保持 Markdown 原始顺序，在同一张卡片内纵向渲染。音视频默认不得自动播放；插件内开始播放任一音视频时必须暂停其他音视频。刷卡索引变化时，离屏音视频必须暂停且不得重置播放进度；销毁视图前必须暂停全部音视频。

Frontmatter 默认折叠，可以展开查看，但不能编辑。

每个 Markdown 渲染实例必须具有可销毁的生命周期。卡片离开视口并被回收时，应卸载对应渲染组件。

### 5.3 原生交互只读化

复用原生渲染时，必须禁用可能写回源文件的交互：

- 任务复选框只能显示，不能切换；
- Properties 只能展开和折叠；
- 不接受向卡片拖入文件、文本或附件；
- 不创建未解析 WikiLink；
- 嵌入内容不得触发源文件修改。

文本选择、复制、内部导航和外部链接正常可用。

## 6. 单卡视图

- 卡片在插件内容区居中；
- 显示文件路径、标题、基础文件信息和完整 Markdown；
- 卡片使用固定宽度和高度；
- 长内容只在卡片内部纵向滚动；
- 插件页面本身不得形成第二层纵向滚动；
- 提供小、中、大尺寸，并允许微调；
- 卡片尺寸为全局插件设置；
- 提供“刷卡”入口；进入后当前文件固定为第一张，其父文件夹递归范围内的其他 Markdown 随机排列；
- 不显示任何编辑或处理操作。

点击内部 WikiLink 时，在插件内打开目标单卡，并保留前进、后退历史。返回文件夹视图时应恢复布局、选中节点和图谱视口。

## 7. 文件夹视图

### 7.1 范围

- 递归包含当前文件夹和全部子文件夹中的 Markdown；
- 无关系的 Markdown 也必须出现；
- 文件夹首次打开时默认显示关系图谱；
- 再次打开时恢复该文件夹上次使用的布局。

### 7.2 顶部工具栏

固定提供：

- 关系图谱；
- 网格；
- 瀑布流；
- 列表；
- 刷卡；
- 只读状态提示。

按当前布局显示卡片尺寸、摘要/全文、网格列数或图谱画布控制。

工具栏不得出现搜索、筛选、排序、新建、编辑、工作流或 AI 入口。

### 7.3 网格

- 默认按文件创建时间排列；
- 支持固定列数和自动适应；
- 支持摘要和完整 Markdown 两种模式；
- 长内容在卡片内部滚动；
- 点击卡片进入单卡视图。

### 7.4 瀑布流

- 卡片宽度统一；
- 卡片高度随内容变化；
- 排列顺序与网格一致；
- 支持摘要和完整 Markdown 两种模式；
- 卡片不得跨列断开。

### 7.5 列表

- 左侧显示文件标题列表；
- 右侧显示选中文件的完整 Markdown；
- 初次进入选择排序后的第一张卡片；
- 切换列表项只更新右侧内容；
- 左右面板宽度按文件夹保存。

### 7.6 刷卡

- 每屏只显示一张完整 Markdown 卡片，使用纵向滚动吸附切换；
- 文件夹范围内的卡片随机排列，“换一批”重新随机，当前卡片保持第一张；
- 长文优先在卡片内部滚动，到达顶部或底部边界后才切换上一张或下一张；
- 支持滚轮、触控板、上下方向键、PageUp、PageDown、空格键和界面按钮；
- 仅渲染当前卡前后有限窗口，切换时及时释放离屏 Markdown 组件。

## 8. 关系图谱

### 8.1 关系来源

图谱只读取：

- Markdown 正文中的 WikiLink；
- frontmatter 任意层级值中的 WikiLink。

当前文件是 source，WikiLink 目标是 target，关系保留方向。

同一 source-target 只绘制一条连线，但保留：

- 正文链接来源；
- frontmatter 链接来源；
- frontmatter 字段路径形成的关系类型。

不得根据标签、文件夹、文本相似度或 AI 生成关系。

### 8.2 节点

图谱显示四类节点：

1. 文件夹范围内的普通 Markdown；
2. 没有关系的独立 Markdown；
3. 与内部节点直接相连的一层外部 Markdown；
4. 目标不存在的未创建节点。

外部节点只显示标题和路径，不继续递归扩展。未创建节点使用虚线样式，点击后只显示目标名称和来源，不创建文件。

### 8.3 缩放层级

- 远距离：标题；
- 中距离：标题和摘要；
- 近距离：完整 Markdown 卡片。

完整 Markdown 只在节点位于视口内且达到近距离阈值时渲染。

### 8.4 交互

图谱必须支持：

- 平移和缩放；
- 拖动节点；
- 首次自动布局；
- 保存节点位置；
- 适应全部节点；
- 定位当前节点；
- 重新自动布局；
- 恢复保存布局；
- 选中节点和直接相邻节点突出；
- 连线标签按需显示或始终显示。

点击节点后，在图谱右侧打开完整 Markdown 卡片，不离开图谱，也不改变图谱视口。

## 9. 状态保存

插件配置可以保存：

### 全局设置

- 卡片宽度和高度；
- 尺寸预设；
- 圆角、阴影、间距和内容密度；
- 默认网格列数策略。

### 文件夹设置

- 最后使用的布局；
- 各布局的摘要或全文模式；
- 网格列数策略；
- 图谱节点位置、缩放和平移；
- 列表面板宽度；
- 最后选中的文件。

### 上次视图

- 单卡或文件夹模式；
- 目标路径；
- 当前布局和选中文件。

状态损坏时回退默认值，不影响 Markdown 文件。

## 10. 增量刷新

插件监听 Obsidian 的文件和元数据事件。

- 新建 Markdown：加入受影响的文件夹范围；
- 修改 Markdown：刷新该卡片及其相关连线；
- 删除 Markdown：移除节点，仍被引用时显示为未创建节点；
- 重命名或移动：刷新路径和范围归属；
- 附件变化：只刷新当前已渲染且引用该附件的卡片。

事件突发时应合并重复刷新。单文件变化不得触发全部正文重新读取。刷新时尽量保留当前视口、节点位置和阅读滚动位置。

## 11. 只读安全

生产代码不得调用用于修改 Vault 内容的 API，包括：

- `Vault.create`；
- `Vault.modify`；
- `Vault.append`；
- `Vault.delete`；
- `Vault.rename`；
- `FileManager.renameFile`；
- `FileManager.processFrontMatter`；
- Adapter 的文件写入、删除和重命名方法。

唯一允许的写入是 Obsidian 插件自己的配置保存机制。

项目必须提供静态检查，扫描生产源码中的禁止写 API。验收时还必须比较测试 Vault 操作前后的内容和路径快照。

## 12. 性能要求

首版以 10,000 个 Markdown 文件的 Desktop Vault 验收。

实现必须满足：

- 初次进入只读取文件和元数据；
- 不预读全部正文；
- 网格、瀑布流、列表和刷卡使用虚拟化；
- 图谱使用视口裁剪；
- 离开视口的 Markdown 渲染组件及时释放；
- 修改一个文件不重建全部卡片；
- 1440 × 900 下无页面级横向溢出；
- 连续切换布局和节点后，渲染组件和监听器不持续增长。

性能验收必须记录测试 Mac、Obsidian 版本、Vault 规模、DOM 数量、正文读取数量和内存表现。

## 13. 视觉要求

继承已确认原型：

- 顶部布局切换；
- 中央关系图谱；
- 右侧完整 Markdown 卡片；
- 内部、外部和未创建节点的视觉区分；
- 当前节点及相邻关系突出；
- 只读状态可见。

正式插件必须跟随 Obsidian 深色和浅色主题，使用 Obsidian CSS 变量，并将全部样式限制在插件根容器内。

原型中的绝对定位节点、mock 数据、内联 CSS和 JavaScript 不进入正式实现。

## 14. 验收清单

第一版必须在真实 Obsidian Desktop 中通过：

- [ ] Ribbon 能按当前上下文打开单卡或文件夹视图；
- [ ] 任意普通 Markdown 无需专属 Schema 即可显示；
- [ ] Frontmatter、Callout、代码、图片、附件和 WikiLink 正确渲染；
- [ ] 任务复选框、Properties 和嵌入保持只读；
- [ ] 长 Markdown 只在卡片内部滚动；
- [ ] 文件夹递归范围正确，且包含无关系文件；
- [ ] 图谱关系方向、去重和关系类型正确；
- [ ] 外部节点和未创建节点符合边界；
- [ ] 图谱节点可拖动、保存和恢复位置；
- [ ] 点击节点在右侧打开完整卡片；
- [ ] 网格、瀑布流、列表和刷卡正常切换；
- [ ] 刷卡随机顺序、单卡优先、长文边界切换和键盘操作正确；
- [ ] 文件变化只增量刷新受影响内容；
- [ ] 重启 Obsidian 后恢复插件设置；
- [ ] 10,000 文件 Vault 验收通过；
- [ ] 1440 × 900 真实窗口无横向溢出；
- [ ] 操作前后 Vault 内容和路径快照一致；
- [ ] 没有实现任何产品非目标。

## 15. 建议实施顺序

1. 插件骨架、自定义视图和只读静态检查；
2. 单卡原生 Markdown 渲染；
3. 文件夹递归读模型；
4. 网格、瀑布流和列表；
5. WikiLink 关系解析和图谱；
6. 布局与会话状态保存；
7. 增量刷新；
8. 万级 Vault 优化；
9. 真实 Obsidian Desktop 验收。

每个阶段都必须保持只读，不能在最后阶段才补安全边界。
