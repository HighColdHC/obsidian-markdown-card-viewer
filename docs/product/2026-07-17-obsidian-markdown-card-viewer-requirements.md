## 1. 文档目的

本文固定本项目重新确认后的完整产品边界，供后续设计、实现和验收使用。

项目不再建设“本地卡片工作台”，也不负责信息采集、卡片处理、工作流、Agent、脚本或 skill。旧工作台需求已经归档，仅供追溯，不再约束当前产品。

后续实现不得在没有新产品决策的情况下扩展本文边界。

## 2. 产品定位

本项目是一个 Obsidian Desktop 插件，只解决两个问题：

1. 将 Vault 中已有的 Markdown 文件渲染为卡片，并用可调整布局查看卡片及其显式链接关系；
2. 使用地址和 Token 手动从 InfoOS 拉取卡片，将完整正文和附件物化到插件受管目录。

“卡片”只是 Markdown 文件的视觉呈现形式，不是新的业务对象或数据模型：

- 一个 Markdown 文件就是一张卡片；
- 一个文件夹就是一个多卡片查看范围；
- Markdown 和附件仍由 Obsidian Vault 管理；
- 插件不要求用户采用专属 Schema；
- 除 InfoOS 受管目录外，插件不改变任何 Vault 内容。

## 3. 产品边界

### 3.1 插件负责

- 读取 Vault 中已有的 Markdown 文件；
- 将单个 Markdown 完整渲染为一张卡片；
- 将文件夹及其子文件夹中的 Markdown 渲染为多卡片视图；
- 提供关系图谱、网格、瀑布流、列表和纵向刷卡布局；
- 从 Markdown 正文和 frontmatter 中读取显式 WikiLink 关系；
- 在 Markdown 变化后增量刷新受影响的卡片和关系；
- 在插件自身配置中保存界面、布局和图谱位置。
- 测试 InfoOS 连接并手动拉取新增或变化的卡片；
- 将 InfoOS 完整正文和附件写入用户指定的受管目录。

### 3.2 明确非目标

插件不负责：

- 除手动 InfoOS 拉取外的采集、同步、导入或自动落地内容；
- 创建、编辑、重写、移动、重命名、删除或归档文件；
- 卡片状态、工作流、流转记录或操作账本；
- 脚本、skill、Agent、AI 或其他确定性内核；
- 加载、执行、调度或管理外部脚本与 skill；
- 搜索、筛选、用户排序或复杂查询；
- 语义关联、相似度计算或自动生成关系；
- 除冻结的 InfoOS 只读插件接口外的外部系统集成；
- 移动端支持；
- 独立于 Obsidian 的编辑器、数据库或主题系统。

## 4. 入口与上下文

插件在 Obsidian 左侧 Ribbon 提供唯一主入口。

点击入口后按当前上下文打开：

1. 当前打开 Markdown 时，进入该文件的单卡视图；
2. 当前选中文件夹时，进入该文件夹的多卡片视图；
3. 没有明确文件或文件夹上下文时，恢复上次关闭时的视图；
4. 内部链接跳转保留插件内的前进、后退历史。

入口可以打开新的 Obsidian 自定义视图，但不得替换或修改原生文件资源管理器和 Markdown 编辑器。

## 5. Markdown 支持范围

### 5.1 文件识别

- Vault 中任意 Markdown 文件都可以显示为卡片；
- 不要求 `card: true` 或其他专属标记；
- 不要求固定 frontmatter 字段；
- 缺少标题时，以文件名作为卡片标题；
- 文件内容异常时显示只读错误状态，不修改源文件。

### 5.2 渲染能力

插件复用 Obsidian 原生 Markdown 渲染能力，支持：

- 标题、段落、列表、任务列表、引用和表格；
- 代码块、数学公式和 Callout；
- WikiLink、标签和脚注；
- 图片、视频、音频、PDF及其他 Obsidian 原生嵌入；
- 当前 Obsidian 主题和其 Markdown 样式。

具体呈现规则：

- Frontmatter 默认折叠，用户可展开查看全部属性；
- 图片自适应卡片宽度，点击后调用 Obsidian 的原图查看能力；
- 视频、音频、PDF和嵌入使用 Obsidian 原生组件；
- 多个图片和音视频保持 Markdown 原始顺序，在同一张卡片内纵向显示；
- 音视频默认不自动播放；插件内同一时刻只允许一个音视频播放；
- 刷离当前卡片时自动暂停音视频并保留进度，刷回时不自动续播；离开当前视图时自动暂停；
- 内部链接在插件内打开目标单卡视图；
- 外部链接沿用 Obsidian 默认外链行为。

## 6. 单卡视图

单卡视图用于完整查看一个 Markdown 文件：

- 卡片在插件面板中居中显示；
- 卡片完整渲染 Markdown，不以摘要替代正文；
- 卡片使用固定高度，超出内容在卡片内部纵向滚动；
- 卡片宽度和高度提供预设档位，并允许滑块微调；
- 卡片尺寸作为全局插件设置，对所有文件夹生效；
- 进入内部链接后可返回来源卡片或原多卡片视图；
- 可从当前卡片进入纵向刷卡视图；当前卡片固定为第一张，其父文件夹中的其余 Markdown 随机排列；
- 单卡视图不提供编辑、状态变更或其他处理动作。

## 7. 文件夹多卡片视图

### 7.1 查看范围

- 一个文件夹对应一个多卡片查看范围；
- 默认递归包含该文件夹的全部子文件夹；
- 无关系的 Markdown 也必须出现在视图中；
- 插件不得因为内容或关系缺失而静默排除文件。

### 7.2 布局

文件夹默认打开关系图谱，用户可以切换：

1. 关系图谱；
2. 网格；
3. 瀑布流；
4. 列表；
5. 刷卡。

布局行为：

- 网格支持固定列数和按可用宽度自动适应；
- 瀑布流使用统一卡片宽度和内容高度排列；
- 列表采用左侧文件列表、右侧完整卡片的双栏结构；
- 刷卡每屏显示一张完整卡片，纵向吸附切换并随机排列；长文先在卡片内部滚动，到达边界后再切换卡片；
- 刷卡支持滚轮、触控板、上下方向键、PageUp、PageDown 和空格键，并可重新随机排列；
- 网格、瀑布流和列表可以分别选择摘要模式或完整内容模式；
- 非图谱布局默认按 Obsidian 文件元数据中的创建时间排列；
- 第一版不提供搜索、筛选或用户排序控件。

### 7.3 文件夹级保存

每个文件夹独立保存：

- 最后使用的布局；
- 各布局的摘要或完整内容模式；
- 网格的固定列数或自动适应选择；
- 图谱视口、缩放级别和节点位置；
- 列表左右面板宽度；
- 该文件夹最后查看的卡片。
- 刷卡随机种子和当前位置。

## 8. 关系图谱

### 8.1 关系来源

图谱只读取确定性的显式关系：

- Markdown 正文中的 WikiLink；
- frontmatter 任意字段值中的 WikiLink。

关系规则：

- 当前文件指向 WikiLink 目标，连线保留方向；
- frontmatter 字段名可以作为关系类型；
- 正文和 frontmatter 中的重复关系合并为一条连线；
- 合并后保留关系来源和全部关系类型；
- 不依据标签、同文件夹、文本相似度或 AI 推断创建关系。

### 8.2 节点类型

图谱包含：

- 当前文件夹及其子文件夹中的普通节点；
- 没有任何关系的独立节点；
- 与当前范围直接相连的文件夹外节点；
- 指向不存在 Markdown 的未创建节点。

边界规则：

- 文件夹外节点只展开一层，不递归扩展整个 Vault；
- 外部节点只显示标题和所在路径；
- 未创建节点使用虚线样式；
- 点击未创建节点只显示链接名称和来源，不创建文件。

### 8.3 分级渲染

图谱节点按缩放级别分三级显示：

1. 远距离：标题；
2. 中距离：标题和摘要；
3. 近距离：完整 Markdown 卡片。

只有进入视口或达到对应缩放级别的节点才加载更多内容，不允许启动时完整渲染所有 Markdown 正文。

### 8.4 图谱交互

- 支持缩放、平移和拖动节点；
- 首次打开文件夹时自动布局；
- 用户拖动后的节点位置按文件夹保存；
- 点击节点后在图谱右侧打开完整卡片；
- 选中节点时突出它及其直接相邻节点，弱化其他节点；
- 提供放大、缩小、适应全部节点、定位当前节点、重新自动布局和恢复保存布局；
- 连线标签默认按需显示，用户可切换为始终显示；
- 多种关系合并到同一连线，并展示多个关系标签。

以上交互只改变显示状态，不改变 Markdown 或链接关系。

## 9. 布局与视觉设置

### 9.1 顶部工具栏

顶部工具栏提供高频查看控制：

- 布局切换；
- 卡片尺寸；
- 网格固定列数或自动适应；
- 摘要或完整内容模式；
- 图谱缩放和画布控制。

### 9.2 插件设置页

设置页提供：

- 卡片宽度和高度；
- 卡片背景；
- 圆角；
- 阴影；
- 卡片间距；
- 内容密度。

插件默认跟随当前 Obsidian 主题，只使用 Obsidian CSS 变量扩展卡片样式，不建设独立主题市场。

## 10. 数据与受控写入保证

插件允许写入自身配置数据，用于保存：

- 全局卡片尺寸和视觉设置；
- 文件夹布局设置；
- 图谱节点位置和视口；
- 上次打开的视图和导航状态。
- InfoOS 地址、Token、目标目录和本地增量索引。

插件不得修改非 InfoOS 受管内容，包括：

- Markdown 正文；
- Frontmatter；
- 文件名和路径；
- 非受管 Vault 文件夹；
- 非受管附件；
- WikiLink 或关系。

插件只允许在目标目录创建或更新带 `infoos_managed: true` 且身份匹配的 Markdown 和附件。路径冲突时不得覆盖。插件不建立业务数据库；同步索引和渲染缓存必须可丢弃、可重建，不能成为内容真相源。

## 11. 更新与性能

### 11.1 增量更新

插件监听 Obsidian 提供的文件和元数据事件：

- 新增 Markdown 时，只加入受影响的文件夹视图；
- 修改 Markdown 时，只刷新对应卡片及其关系；
- 重命名、移动或删除由 Obsidian 或其他工具完成时，插件只刷新显示状态；
- 更新过程中保留用户当前的滚动、缩放和选中状态；
- 不通过回写源文件修复或同步任何状态。

### 11.2 规模目标

第一版以包含 10,000 个 Markdown 文件的 Vault 为验收规模。

实现必须采用：

- 元数据优先读取；
- 正文按需加载；
- 网格、瀑布流和列表虚拟化；
- 图谱视口裁剪；
- 节点分级渲染；
- 文件与关系的增量更新；
- 可丢弃的内存缓存。

不得以启动时读取并渲染全部正文作为实现方案。

## 12. 第一版验收标准

第一版必须通过以下真实 Obsidian Desktop 验收：

1. 点击 Ribbon 能根据当前上下文进入单卡、文件夹或上次视图；
2. 任意普通 Markdown 无需专属 Schema 即可显示；
3. 单卡能完整渲染正文、frontmatter、图片、附件、WikiLink 和 Callout；
4. 长内容能在固定高度卡片内滚动；
5. 文件夹递归包含全部子文件夹 Markdown；
6. 图谱、网格、瀑布流和列表可以切换并恢复文件夹级设置；
7. 正文和 frontmatter WikiLink 能生成方向正确、去重后的关系；
8. 无关系节点、文件夹外节点和未创建节点均按本文规则显示；
9. 图谱支持分级渲染、拖动、保存位置和右侧完整卡片；
10. 文件变化后只增量刷新受影响的卡片与关系；
11. 关闭并重新打开 Obsidian 后能恢复插件布局配置；
12. 10,000 个 Markdown 文件下不会一次渲染全部正文；
13. 自动化检查和真实 Vault 验证均不得发现插件修改受管目录之外的 Markdown、frontmatter、附件或路径；
14. 第一版只在 Obsidian Desktop 上承诺完整支持。
15. 使用真实 Linux InfoOS、临时 Token 和 SSH 隧道完成连接、首次拉取、附件显示及第二次零变化验收。

## 13. 需求变更规则

以下任何新增都属于产品边界变更，需要先更新本文，而不是直接进入实现：

- 写入或编辑非 InfoOS 受管 Markdown；
- 卡片处理动作或工作流；
- 搜索、筛选、排序或查询语言；
- AI、Agent、脚本或 skill 集成；
- 除冻结的手动 InfoOS 拉取外的同步、导入或外部数据源；
- 流转记录、状态或业务对象；
- 移动端支持；
- 基于非显式链接生成关系。

在没有新决策前，本文是本项目唯一有效的产品需求基线。
